# 前言：从一次请求走进网关

API 网关最容易被理解成一个转发地址，也最容易因为这种理解而被低估。一个订单请求从客户端到服务，途中涉及路由、认证、流量治理、连接复用、超时传播、配置发布与监控。任何一个环节都可能把局部故障扩大成系统故障。本书讨论的核心问题是：怎样把这些能力组织成一个可解释、可测试、可演进的请求处理系统。

本书以 Apache ShenYu 为主线。先理解插件链怎样组织处理过程，再理解选择器和规则怎样决定策略范围，然后研究限流、熔断与配置同步。最后把这些问题放进 Spring Cloud Gateway、Kong、Apache APISIX、Higress 与 Envoy Gateway 的架构中比较。连同 ShenYu，一共六种网关。比较围绕控制模型、扩展边界与运维成本展开，不给出脱离环境的性能冠军。

目标读者是有 HTTP、Java 或后端开发经验，希望设计网关、阅读源码或完成技术选型的工程师。阅读 Java 代码需要理解接口、并发和 Reactor 的基本思想；其余章节尽量不依赖某一门语言。没有 Kubernetes 经验的读者可以先完成前十章，再阅读 Gateway API 部分。

贯穿全书的系统是一家虚构的电商平台：订单服务、库存服务、支付服务，以及由合作伙伴调用的开放 API。平台希望将身份校验、租户配额、灰度路由和观测统一起来。示例中的域名与租户均为虚构。

## 版本、证据与阅读约定

ShenYu 源码分析固定在 **v2.6.0** 标签；这不是“最新版本”的声明。书中核对了 `ShenyuWebHandler` 与 `AbstractShenyuPlugin` 的实际实现，并在参考资料中给出固定链接。其他产品按各自官方文档解释稳定的架构概念；其配置键、发行包、插件可用性和 Gateway API 支持范围会随版本变化。采用前应锁定版本与对应文档，不能把本书的架构比较理解成跨版本兼容承诺。

标记为“教学模型”的代码用于揭示不变量，不等同于任何项目的源码；标记为“配置示意”的片段不能直接当作部署文件。附录实验使用 Python 标准库，可离线运行。它验证匹配、限流、熔断、配置版本等核心语义，不替代真实网关的集成测试或生产压测。正文中的容量数值均为推导示例，没有声称完成六种产品的基准测试。

阅读路线可以有两条。开发者按顺序阅读，最后完成实验；架构师可先读第 1、10、16、17 章，再回到源码章节验证选型依据。每章末尾的思考题在附录提供参考答案。
